# Formula Apex Spectator

Инжектор-скрипт для наблюдения за пилотами в игре **Formula Apex** (Roblox), совместимый с инжектором **Xeno v1.3.6** (и новее, включая v1.6).

## Возможности
- 🏎️ Автоматическое отслеживание всех пилотов на сервере: скорость, состояние болида (HP).
- 💥 Детектор аварий (крашей): фиксирует момент, когда пилот разбил машину (резкое падение скорости + просадка здоровья).
- 📋 HUD-интерфейс прямо в игре со списком пилотов и логом последних аварий.
- ⏱️ Таймстемпы каждого инцидента — удобно для разборов в лигах.
- 🔗 Опциональная отправка событий об авариях в Discord через Webhook.
- Кнопка скрытия/показа интерфейса («–» / «+»).
- Кнопка закрепления (P): в закреплённом режиме окно не перемещается, фон становится чёрным непрозрачным, окно не перемещается и клики проходят сквозь HUD.
- Кнопка START MONITORING: наблюдение запускается вручную (на старте заезда никто не помечается DNF автоматически), повторное нажатие — STOP и сброс статусов.
- Кнопка CLEAR — очистка лога аварий.
- Кнопка CLEAR — очистка лога аварий/DNF.

## Быстрый запуск (loadstring) — рекомендуется

### Вариант 1: через лоадер (лучше всего)
Лоадер сам скачает актуальный скрипт, покажет уведомления в Xeno и предупредит, если вы не в Formula Apex:

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/kapralchiknn1/formulaapexspectator/main/loader.lua"))()
```

### Вариант 2: напрямую main.lua
Вставьте эту строку в Xeno и нажмите **Execute** (скрипт всегда подтягивается с GitHub, обновлять не нужно):

```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/kapralchiknn1/formulaapexspectator/main/main.lua"))()
```

Готовый лоадер также лежит в файле [`loader.lua`](./loader.lua).

## Ручная установка (Xeno v1.3.6 / v1.6)
1. Запустите Roblox и зайдите на сервер Formula Apex.
2. Откройте **Xeno** и сделайте **Inject/Attach** к процессу Roblox.
3. Скопируйте содержимое файла [`main.lua`](./main.lua) в редактор скриптов Xeno.
4. Нажмите **Execute**.

## Настройка
Все параметры находятся в таблице `CONFIG` в начале `main.lua`:

| Параметр | Описание |
|---|---|
| `REFRESH_INTERVAL` | Частота обновления данных пилотов (сек) |
| `CRASH_SPEED_THRESHOLD` | Порог скорости для детектора краша |
| `CRASH_DAMAGE_THRESHOLD` | Порог HP болида, ниже которого он считается разбитым |
| `STALLED_AFTER_SECONDS` | Через сколько секунд простоя пилот помечается как DNF |
| `SHOW_LOCAL_PLAYER` | Показывать ли самого себя в списке |
| `DEBUG_LOG` | Печатать в консоль результаты поиска машин (для диагностики) |
| `MAX_LOG_ENTRIES` | Максимальный размер лога аварий |
| `WEBHOOK_ENABLED` / `WEBHOOK_URL` | Отправка событий в Discord |

## Диагностика: скрипт не находит машины / нет DNF
Если в HUD пилоты показаны как `[НЕТ МАШИНЫ]` или аварии/DNF не появляются:
1. Запустите диагностический скрипт [`diag.lua`](./diag.lua) в Xeno (или через loadstring):
```lua
loadstring(game:HttpGet("https://raw.githubusercontent.com/kapralchiknn1/formulaapexspectator/main/diag.lua"))()
```
2. Откройте консоль Xeno и скопируйте вывод — там видно, как игра хранит болиды (имена моделей, атрибуты).
3. В `main.lua` включите `DEBUG_LOG = true`, чтобы видеть по каждому игроку, найдена ли его машина.

Причина №1 пропуска DNF: **StreamingEnabled** — машины далёких пилотов выгружаются из клиента,
поэтому они могли не появляться в списке наблюдения. Обновлённый скрипт ищет модели глобально
(включая стриминг-далёкие объекты) и помечает стоящих/разбитых пилотов как DNF даже без прямого доступа к болиду.

## Примечание
Игра может обновляться — если имена моделей/атрибутов болидов изменятся,
адаптируйте функции `getCarForPlayer`, `getCarHealth` и `getCarVelocity`.
